# Plan: REST API Layer + QR Code Scanning for ShoeInventorySystem

## Overview
Add a free REST API layer exposing all existing Manager classes as JSON endpoints, then integrate browser-based QR/barcode scanning using the MIT-licensed `html5-qrcode` library.

---

## Part 1: REST API Layer

### Architecture

Create an `api/` directory at the project root with a simple router and per-resource endpoints. No external PHP frameworks needed — pure vanilla PHP leveraging the existing Manager classes.

```
api/
├── index.php            # Central router + JSON response helpers
├── auth.php             # API key authentication middleware
├── items.php            # GET/POST/PUT/DELETE /api/items
├── stock.php            # GET/POST/PUT/DELETE /api/stock
├── suppliers.php        # GET/POST/PUT/DELETE /api/suppliers
├── transactions.php     # GET/POST/DELETE /api/transactions
└── users.php            # GET/POST/PUT /api/users (admin only)
```

### Database Change: API Keys Table

Add a new `api_keys` table to store access tokens for API consumers:

```sql
CREATE TABLE `api_keys` (
  `id` int(11) NOT NULL AUTO_INCREMENT,
  `key_hash` varchar(255) NOT NULL,
  `label` varchar(100) NOT NULL,
  `user_id` int(10) UNSIGNED DEFAULT NULL,
  `status` enum('active','revoked') NOT NULL DEFAULT 'active',
  `created_at` timestamp NOT NULL DEFAULT current_timestamp(),
  PRIMARY KEY (`id`),
  KEY `user_id` (`user_id`)
);
```

### Authentication Flow

1. Client sends `X-API-Key` header with each request
2. `api/auth.php` hashes the key with SHA-256, looks it up in `api_keys`
3. If valid and active, `$api_user_id` is set and request proceeds
4. If invalid, returns `401 Unauthorized` JSON response

### API Response Format (consistent across all endpoints)

```json
{
  "success": true,
  "data": { ... },
  "message": "Optional message"
}
```

Error:
```json
{
  "success": false,
  "message": "Error description",
  "errors": [...]
}
```

```apache
RewriteEngine On
RewriteCond %{REQUEST_FILENAME} !-f
RewriteCond %{REQUEST_FILENAME} !-d
RewriteRule ^(.*)$ index.php [QSA,L]
```

## Part 2: QR Code Scanning

### Library: html5-qrcode (MIT, free)

- **CDN:** `https://unpkg.com/html5-qrcode`
- No API keys, no usage limits, fully offline-capable
- Supports QR codes, barcodes (EAN, UPC, Code128, etc.)
- Works on desktop (webcam) and mobile (camera)

### Integration Plan

1. **Add `api/item_lookup.php`** — simple endpoint to look up an item by name or ID
   - `GET /api/items?search={query}` already exists, reuse it

2. **Add scan button to stock page** (`frontend/stock.php`)
   - New "Scan QR/Barcode" button in the actions area
   - Opens a modal with camera feed
   - On successful scan, auto-searches items by scanned value
   - Redirects to filtered stock view or pre-fills a transaction form

3. **Add scan button to items page** (`frontend/item.php`)
   - Same scan button for quick item lookup

4. **Create `js/qr-scanner.js`** — shared scanner utility
   - Initializes `Html5QrcodeScanner` in a modal
   - Returns scanned text to a callback function
   - Handles camera permissions gracefully

### Files to Modify/Create

| File | Action | Purpose |
|------|--------|---------|
| `js/qr-scanner.js` | **Create** | Shared QR scanner utility class |
| `frontend/stock.php` | **Modify** | Add scan button + scanner modal |
| `frontend/components/items/add_modal.php` | **Modify** | Add optional "Scan barcode" input for item name |
| `frontend/components/stock/scan_modal.php` | **Create** | Reusable scanner modal HTML |
| `css/base.css` | **Modify** | Add scanner modal styles |

### Scanner Flow

```
User clicks "Scan QR/Barcode" button
  → Scanner modal opens with camera feed
  → User points camera at barcode/QR
  → library decodes value (e.g., "Nike Air Max 90")
  → JS calls GET /api/items?search={decoded_value}
  → Results displayed in modal
  → User selects item → stock page filters to that item
```
